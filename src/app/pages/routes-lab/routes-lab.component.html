Routes · <router-outlet>

A route config maps a URL to a component. The outlet is the slot where that component is inserted. Knowing where to put the outlet is as important as writing the route table — it decides what stays mounted (header, section nav) and what swaps.

What <router-outlet> does

It is not a page and not a layout by itself. It is a placeholder: when the router activates a route, Angular creates that route’s component and projects it into the outlet. No matching outlet → the page has nowhere to appear.

  • Sibling chrome (header, footer) lives outside the outlet and stays up.
  • Whatever is inside the outlet is destroyed and recreated on navigate.
  • Nested routes need a second outlet on the parent that owns those children.

Where to put it · 1 — App shell (required)

Put one primary outlet in the layout that wraps every screen — the piece that should never unmount when you change pages. In this lab that is app-content, between header and footer.

  • app.html → header · content · footer (no outlet here).
  • content.component.html → <router-outlet /> (primary).
  • Home, RxJS, Core, Users, Material… all render in that one slot.

Where to put it · 2 — Componentless parent (no extra outlet)

Sections like /core/* and /basics/* group URLs under a path prefix but do not need their own sub-nav chrome. The parent route has children and no component — a componentless route. Children activate in the nearest ancestor outlet (the app shell). You do not add another outlet for that prefix.

Where to put it · 3 — Feature shell (nested outlet)

Use a parent component + child outlet when a URL family should share UI that stays mounted — section title, sub-nav, filters, side rail. Look above this lesson: the Routes strip (Overview · Lazy · Guards…) is that shell. Click Lazy or Guards — the strip stays; only the body below swaps.

  • Parent route → loadComponent (the shell) + children.
  • Shell template → must include <router-outlet /> for those children.
  • Activation stack: shell → app outlet; child lab → shell outlet.

Decision cheat sheet

  • Whole-app chrome (header/footer) → primary outlet in the app layout.
  • Shared section chrome (sub-nav that must stay) → parent shell + nested outlet.
  • Path prefix only (no shared UI) → componentless parent; no extra outlet.
  • Leaf page (no children) → do not add an outlet.
  • Side panel / aux route → named outlet (advanced; rare).

What you’re using in this app

  • / → Home · /rxjs → RxJS (app outlet only)
  • /core/* · /basics/* · /material/* — componentless parents → app outlet
  • /routes/* — RoutesShell in app outlet + child labs in shell outlet
  • path: '**' → wildcard fallback to Home
