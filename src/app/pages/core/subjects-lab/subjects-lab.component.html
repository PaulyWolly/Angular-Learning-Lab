Subjects · BehaviorSubject

One correction that unlocks this: a plain Subject does not remember “what is now.” It only shouts to whoever is listening at that instant. A BehaviorSubject does remember the current value — so a component that shows up later still gets an answer.

Start here — plain English

Why “late” at all? In an Angular app, components are created at different times. The header might subscribe at startup. A dialog or route page you open later also needs the same data (logged-in user, theme, last search). That second component is a late subscriber — it wasn’t around when the first value was pushed. With a plain Subject it would sit there empty until something happens again. With a BehaviorSubject it immediately gets “whatever is current right now,” without waiting for another click or HTTP call.

Subject ≈ live radio

You turn on the radio now. You hear whatever is broadcast from this moment on. Songs that played before you tuned in? Gone. You missed them.

next('ping') = DJ says something.
Subscribe late = you only hear the next ping.

BehaviorSubject ≈ sticky note

There is always a note on the fridge (it starts with a default). Anyone who walks up — even hours later — still reads the current note right away.

new BehaviorSubject('cream') = first note.
Open a new page later = you still get the latest note immediately.
