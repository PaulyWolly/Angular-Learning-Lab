Components

A component is the main UI building block in Angular: a class + @Component metadata + a template. This lab covers anatomy, inputs (data down), outputs (events up), standalone / imports, and content projection (ng-content).

Anatomy — decorator, class, template

Every screen piece you see is a component. The selector becomes an HTML tag; the class holds state; the template reads that state. The decorator also declares standalone and an imports array (next card).

Standalone + imports

In Angular v20 (and this app), components are standalone by default. That means each component declares what its own template needs in imports: […] — you do not register children in an NgModule.

  • standalone: true — this component is self-contained; list its template dependencies in imports.
  • Child components — e.g. DemoGreeterComponent must be in imports before you can write <app-demo-greeter>.
  • Directives / pipes / modules — e.g. FormsModule for [(ngModel)], RouterLink for routerLink, AsyncPipe for | async.
  • Only what this template uses — don’t import unused pieces; each standalone component opts in explicitly (good for tree-shaking and clarity).
  • When would standalone be false? Legacy NgModule apps. New code and this lab stay on standalone: true.

Content projection — ng-content

Markup between the child’s tags is stamped into <ng-content />. That is different from an input — you project a template, not a string property.

This paragraph lives in the parent template. The panel only provides the chrome; ng-content inserts whatever you nest inside.

Useful for cards, dialogs, layout shells, and reusable wrappers.
