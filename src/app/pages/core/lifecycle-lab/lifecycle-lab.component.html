Lifecycle hooks

Angular calls named methods as a component is created, updated, and destroyed. You import the interface from @angular/core and implement it so TypeScript checks the method exists — the runtime only looks for ngOnInit() by name. Contrast with constructors (create the instance) and components (the class + template).

Start here — import, then implement

Two different imports. A template feature (ReactiveFormsModule, a child component) goes on imports: []. A lifecycle hook is a TypeScript interface: import { OnInit } from '@angular/core' then implements OnInit and write ngOnInit().

  1. create instance — prefer private readonly http = inject(HttpClient) (skip constructor() unless you need super())
  2. ngOnChanges — first input bind (and later when inputs change)
  3. ngOnInit — inputs are set; start HTTP / subscriptions
  4. ngAfterViewInit — this view and @ViewChild are ready
  5. afterNextRender() — browser painted; measure DOM here
  6. ngOnDestroy / DestroyRef — teardown

import + implements (the TypeScript contract)

implements OnInit is a compile-time checklist. Forget the interface and keep ngOnInit() — Angular still calls it. Forget the method and keep implements OnInit — TypeScript errors. That is the whole trick.
