Constructors — when you need one (and when you don’t)

A constructor runs once when Angular creates your component or service class. In modern Angular you often skip it entirely — but interviews still ask why.

Start here — plain English

Usually skip it

Put dependencies in inject(), state in class fields (title = 'Home'), and inputs in input(). Angular builds the class without you writing constructor() { }.

Still need it sometimes

Subclassing (super()), one-time setup that chains off injected deps, or a team that standardizes on constructor(private http: HttpClient).
