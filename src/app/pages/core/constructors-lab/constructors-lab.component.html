Constructors — when you need one (and when you don’t)

A constructor runs once when Angular creates your component or service class. In Angular 16+ you usually skip it and write private readonly http = inject(HttpClient) as a class field. Interviews still ask why. After the instance exists, Angular runs lifecycle hooks (ngOnInit, destroy, …).

Start here — plain English

Usually skip it

Put dependencies on fields with inject(): private readonly http = inject(HttpClient). Same for any service. State stays in fields (title = 'Home'); inputs use input(). No constructor() required.

Still need it sometimes

Subclassing (super()), or reading older code that still uses constructor(private http: HttpClient) — same injector, older syntax.

2. New default — field inject() (not constructor params)

Same injector, two syntaxes. New code: private readonly http = inject(HttpClient). Old code: constructor(private http: HttpClient). Do not mix both for the same dependency.

3. Form setup — still no constructor needed
