NgRx

NgRx is a store for shared app state. You dispatch actions (events), a reducer returns a new state, and selectors read slices for the template. @ngrx/signals is the modern SignalStore path — same idea, fewer files. Local UI still belongs in signals; a tiny shared counter still belongs in a service.

Start here — one-way traffic

Why a store at all? When five distant screens need the same cart, user session, or feature flags, passing inputs down and outputs up gets noisy. A store is a single source of truth: the view never patches state in place — it asks, by dispatching.

View dispatch Action reduce Store select View

Side work (HTTP, timers) lives in an effect: it hears an action, does the async job, then dispatches a success / failure action. The reducer stays a pure function.
