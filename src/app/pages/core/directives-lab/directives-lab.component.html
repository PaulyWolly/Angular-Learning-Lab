Directives

Directives change the DOM or its behavior. Structural add/remove elements (@if, @for, custom *appUnless). Attribute change appearance or behavior of an existing element (ngClass, appHighlight, appModulusColor). Each card pairs Template + TypeScript.

Structural — @if / @for

Attribute — ngClass object vs ternary

Stress this: { } are not “ngClass wrappers.” They create a JavaScript object (className: boolean). A ternary returns a string — so it has no braces. Mixing them ({ n % 5 === 0 ? 'green' : 'red' }) is invalid.

modNumber % 5 === 0 → green, else red

Object form — { } required

{{ modNumber }}

Ternary form — no { }

{{ modNumber }}

Also: ngStyle with tone

tone = {{ tone }}

Custom attribute — appModulusColor (parity)

Interpolation shows the number; the directive sets style.color from n % 2 — even → teal, odd → red. Same idea as many interview “color by parity” demos.

score = {{ score }} ({{ score % 2 === 0 ? 'even' : 'odd' }})

Custom structural — *appUnless

Yes — in real apps you would usually write @if (!hideHint) and stop. We go the longer route on purpose: *appUnless is the classic interview exercise for TemplateRef + ViewContainerRef — the engine behind * microsyntax (and behind @if / @for themselves). Learn it once here so you can explain how structural directives add/remove DOM, not only how to flip a boolean.
