Producer → Observable → Observer

In this lab the producer is HttpClient fetching /users. It does the real work and pushes the result out. users$ is the Observable recipe that describes that work. The Observer is only the callbacks you pass to subscribe — it listens; it does not fetch.

Observable

Lazy recipe — like an uncalled function.

  • Holds / describes the producer’s work
  • Harmless until someone subscribes
  • Cold HTTP: work runs when subscribed (until shared)

Observer

Object you pass to subscribe.

  • {{ '{' }} next, error, complete {{ '}' }}
  • next — you receive each value the producer sends
  • complete — you register this callback; the producer calls it when finished (e.g. HTTP response done). You do not call complete yourself.
Also: Subscription. That is the active listening session between producer and Observer — what you unsubscribe or tear down with async pipe / takeUntilDestroyed(). Not the same as ngOnDestroy itself.
